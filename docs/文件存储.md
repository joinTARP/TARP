# 文件存储约定

## 分层与入口

- `packages/core/src/node/storage/file-queue.ts`：按文件协调当前主进程内的操作。同文件串行，不同文件可以并行；失败后继续处理后续操作。已有路径及未创建文件的父目录通过 `realpath` 归一化。
- `packages/core/src/node/storage/write-file-atomic.ts`：在目标目录中使用独立临时文件，完整写入后通过 `rename` 替换目标；失败时清理临时文件，不先删除原目标。`stageFileAtomic` 支持业务在暂存后选择发布或取消。
- `packages/core/src/node/storage/structured-file.ts`：组合解析、业务校验、目录创建、原子写入及完整读改写。默认使用 JSON，可以提供 JSON/TOML 等 codec；存储层不维护业务缓存。

应用常规配置、玩家身份与游戏默认配置、语音连接保存在 `settings.json` 的 `app`、`game`、`tts` 分组，由桌面主进程的 `config/app-settings.ts` 共用同一文件队列读改写，文件权限为 `0600`。自定义服务商与模型定义保存在 `models.json`，采用 pi 模型格式并由应用原子保存；AI API Key 与订阅凭据由 pi 管理在 `auth.json` 中。资料窗口位置使用独立的结构化存储。房间资料、笔记、开局与队伍状态保存在 `adventure.json`，由核心的 `sessions/room-storage.ts` 按分组读改写；本局设置独立保存在 `settings.json`，由 `sessions/room-settings.ts` 管理；游戏文档复用原子写入能力，由房间业务负责事务协调。只读模组解析、媒体读取、模组复制和 pi 自己管理的会话文件使用各自入口，保留路径、安全及文件格式规则。

## 新增配置的用法

```ts
const file = structuredFile(path, {
  validate: (value) => schema.parse(value),
  missing: () => defaultValue,
  fileMode: 0o600,
  directoryMode: 0o700,
});

const value = await file.read();
await file.update((current) => ({ ...current, enabled: true }));
await file.flush();
```

`update` 在队列内重新读取文件，然后执行修改、校验及保存。修改已有配置时优先用该接口，避免在队列外读取旧快照再 `write`。`write` 用于完整替换或初始化，保存的是调用时的数据快照。`read` 等待此前登记的操作；`flush` 等待此前操作结束，但不会重复报告此前保存的错误，保存调用方应处理自己的异常。

`missing` 只在 `ENOENT` 时调用；未提供则保留该错误。格式损坏、字段错误及其他文件系统错误都不会触发默认值。解析和校验错误只提供路径、格式或字段名，避免把配置原文及密钥放进错误提示；各业务可以转换为自己的错误类型。是否允许重置已有损坏文件由业务决定，应用配置的补丁保存必须先成功读取。

不要在同一文件的 `update` 回调或 `withFileMutation` 回调中再次调用该文件的异步存储接口，否则会等待自己持有的队列。业务需要更大范围的锁时，先获取业务锁，再调用文件层；不要反向获取。

## 业务边界

冒险的 `adventure.json` 和 `settings.json` 各自使用同步接口，避免一次读改写中产生异步间隙；初始化只用于尚未发布的 staging 目录，后续修改只更新所属文件和分组，不跨文件回写旧快照。一个目标的日常修改应统一使用同步或异步接口，同步接口不会等待异步队列。

玩家和语音服务保留各自的业务队列，不缓存落盘配置；每次读取使用最新分组，保存时在统一文件队列内保留其他分组。pi 的认证存储负责 AI 凭据的文件锁和读改写，`ModelRuntime` 负责登录、退出及 OAuth 刷新；订阅服务只桥接界面交互。同一配置目录应复用同一个服务实例，协调同分组的业务读改写及语音任务生命周期。

游戏文档由房间锁协调校验、文件发布与角色索引更新；批量更新先校验全部最终候选并暂存全部文件，再依次替换目标。原子替换只保证单个文件的发布，批量发布也不提供跨文件回滚或文件与数据库之间的崩溃恢复事务；房间各文件职责见[存档格式](游戏房间存档格式.md)。模组路径和符号链接的安全校验由业务层保留，队列中的路径归一化不是访问授权。

当前队列只协调本进程，不能阻止其他进程或外部编辑器写入。原子替换不包含 `fsync`，不承诺断电持久性；Windows 的替换与文件占用行为仍需实机验收。
