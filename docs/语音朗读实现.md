# 语音朗读实现

语音操作和模组音色配置统一维护在官网：「语音朗读」、「模组角色声音」。本文维护提供商接口、任务协调、凭据、播放协议及扩展验证。

## 消息与声音解析

主进程解析房间冻结模组、房间声音覆盖和创建时保存的语音配置，客户端请求携带房间及说话人标识，不直接提交上游凭据。声音描述不参与文字剧情提示词。主持覆盖保存在冒险目录 `settings.json` 的 `tts.host`，队友覆盖保存在 `adventure.json.party.companions` 中对应席位的 `voice`，不改模组原件；合成取配置快照，设置变更只影响后续任务。

`tts.characters` 的键在元配置加载时归一化为不带格式扩展名的文档标识，同一标识配置多份音色时报错。队友的规范 `sourcePath`、预写消息的 `speakerPath` 和 AI 回复 NPC 标签的 `path` 都按该标识匹配，因此作者文件转成会话 JSON 后继续继承原音色。公开称呼不参与音色匹配，缺少预设时继承冒险默认声音。

自动朗读只接收新完成的公开主持、NPC、队友和预写消息，排除玩家、内部回合、工具及选择卡。读取历史或重连时不重播，长文本按句切块，每块最多 1000 个 UTF-16 码元；清理 Markdown 展示标记、图片、代码块和链接地址，不展开嵌入文档。每窗口共用播放器，播放当前消息时预取下一段；关闭房间语音时终止本端队列和订阅，文字生成不受合成失败影响。

## 配置和播放

- 应用语音连接保存在 `~/.tarp/settings.json.tts.connections`，游戏默认声音在 `game.defaults.tts`，支持 `TARP_HOME` 覆盖目录。创建时将无凭据配置复制到冒险 `settings.json.tts`。
- API Key 写在 `tts` 分组中，文件权限为 `0600`；普通配置接口只读取 `app` 分组，语音接口返回脱敏投影，不向渲染器回显密钥。
- 自动朗读按冒险独立保存，输入栏只改本局值。合成按冒险 `config.provider` 查询当前应用凭据；切换应用默认供应商不改变旧冒险，删除连接后相关冒险不可用，重新连接后恢复，不回退到其他供应商。不同服务商不会互相复用密钥。
- 声音优先级为个人覆盖、冻结模组声音、冒险默认声音。队友席位的 `defaultVoice` 是新增时复制的模板兜底，低于模组声音；主持默认声音和 NPC 兜底从本局配置读取。
- 语音会发送到所选服务商；MiMo 适配器使用 `https://api.xiaomimimo.com/v1/chat/completions`。Token Plan 专属端点尚未提供配置。
- 每个客户端窗口共用一个播放器。手动朗读和试听会替换当前队列；停止或离开房间时会取消本端订阅与播放；没有其他订阅者时才取消上游合成，忽略迟到结果。
- 主进程按服务商、模型、音色、风格、文本和凭据缓存近期合成结果，Base64 内容上限约 32 MiB。缓存只保留在内存，重启后清空。

## 扩展服务商

扩展点位于 `apps/desktop/src/main/tts/provider.ts` 的 `TtsProvider`：

```ts
interface TtsProvider {
  info: TtsProviderInfo;
  synthesize(input: TtsRequest): Promise<TtsAudio>;
  stream?(input: TtsRequest): AsyncIterable<TtsPcmChunk>;
}
```

新增服务商时：

1. 在 `apps/desktop/src/main/tts/` 新建适配器，将服务商的鉴权、请求体、音频返回格式转换为通用 `TtsAudio`（Base64 数据和 MIME 类型），支持流式时实现 `stream`，输出带采样率、声道数的 PCM16LE 块。实现必须传递取消信号，并设置请求超时。
2. 提供服务商标识、模型、音色和默认配置，将适配器加入 `TtsService` 的服务商注册列表。设置界面从目录读取选项。
3. 需要向用户展示的预期错误使用 `TtsError`，避免直接回显上游响应体或凭据。
4. 添加协议转换和凭据隔离测试。`TtsService`、桌面 RPC、播放队列和聊天按钮可以复用。

`apps/desktop/src/shared/tts.ts` 是通用协议，`apps/desktop/src/main/tts/mimo.ts` 是 MiMo 适配器，`apps/desktop/src/renderer/src/features/tts/speech-player.ts` 负责队列和播放。聊天模型由 pi-ai 处理；TTS 直接合成已生成的公开正文。

`tts.stream` 支持 PCM 分块和完整音频两种事件，不支持流式的服务商自动回退到完整音频。`tts.synthesize` 也复用同一合成任务，汇总后返回完整音频。朗读在 LLM 公开正文生成完成后开始，避免播出尚未稳定的文字。角色声音由房间冻结的模组副本提供，朗读请求携带房间和说话人标识，主进程解析对应配置。

## 单进程任务协调

| 资源         | 归属与锁范围                                                      | 释放方式                                                    |
| ------------ | ----------------------------------------------------------------- | ----------------------------------------------------------- |
| 配置与凭据   | `TtsService` 业务队列与统一配置文件队列，读取时取配置快照         | 不跨网络等待持锁；原子文件替换                              |
| 合成任务     | `SharedTtsJobs` 按配置、文本、凭据摘要和凭据世代合并请求          | 最后一个订阅者退出才取消上游；失败可以重新申请              |
| 上游连接     | 全局最多 2 个活动合成，最多 16 个保留任务（含排队及仍在消费的流） | 完成、失败或取消后释放；排队取消直接移除                    |
| 流式广播     | 每个订阅者独立游标，同任务最多 32 人；晚加入者从第一块重放        | 单人停止不会影响其他人；所有订阅退出后清理                  |
| 音频缓冲     | 单任务 Base64 不超过 24 MiB，全局流缓冲不超过 32 MiB              | 超限终止任务并提示重试；完整 PCM 汇总另限 16 MiB / 活动任务 |
| 完整音频缓存 | LRU，Base64 不超过 32 MiB，完整成功后才写入                       | 淘汰、断开凭据或退出进程；旧任务不能重新填充已清空的缓存    |
| 本地播放     | 每窗口一个播放器和复用的 AudioContext；节点归单次播放所有         | 停止清理本次节点和订阅，不关闭后续播放复用的设备上下文      |

设置锁、任务登记、播放控制互相独立。登记和引用计数在同一 JavaScript 事件循环内同步完成，不在登记期间等待网络；旧任务结束前检查身份，防止误删同键的新任务。合成使用配置快照，期间修改设置只影响新任务。服务商请求超时 90 秒，活动任务保护超时 120 秒；服务商适配器必须响应取消信号。

以上限制针对主要音频载荷，并非整个进程的 RSS 上限：Base64、解码后的 PCM、WAV 包装和 IPC 序列化有额外开销。任务共享限于单个主进程内使用同一份本地凭据的请求；没有跨机器锁或跨用户缓存。

## MiMo 协议与验证

MiMo 使用 Chat Completions 格式：待朗读文字放在 `assistant` 消息。基础 TTS 将风格说明放在 `user` 消息，在 `audio` 中指定预置 `voice`；VoiceDesign 必须在 `user` 消息中提供音色描述，不传预置 `voice`。两者的非流式调用均指定 `format: "wav"`。非流式结果读取 `choices[0].message.audio.data`。流式使用 `stream: true`、`audio.format: "pcm16"`，读取 SSE 的 `choices[0].delta.audio.data`；基础 TTS 的流式音频为 24 kHz、单声道、PCM16LE。VoiceDesign 官方当前只有兼容式流式接口，推理结束后一次返回；本应用使用非流式 WAV，避免显示并不存在的低延迟流式进度。客户端保留跨块的不完整采样帧，并按音频时钟连续调度。中断的流不会进入完整音频缓存。

官方资料：[MiMo 语音合成指南](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis)。

从 `apps/desktop/` 执行定向测试：

```bash
bun run test src/main/tts src/shared/speech-text.test.ts src/renderer/src/features/tts
```

这些测试通过模拟服务验证协议、凭据、缓存、消息去重、分块和取消。真实音色、延迟与账户权限需要在填入有效 MiMo API Key 后通过“试听”验证。
