# 房间增量同步实现

同步结构标识是 `game-document-overlay-v1`，协议版本为 `1`。文档版本用数字 `revision` 表示，客户端会检查它是否为正的安全整数。开发版本的兼容策略见[存档格式](游戏房间存档格式.md)。

## 数据与计算边界

文档是游戏状态的来源。各客户端从本地 `session/module/` 读取同一份冻结模组，主机同步本局原始文档相对模组的累计覆盖。JSON、TOML 和 Markdown 归一化为结构化文档；不传目录、原文件文本或图片字节。

房间实体仅包含 `id`、数字 `revision`、可选角色归属 `character` 和原始 `document`。路径、名称、类型及正文来自 `document`，业务字段仅存放在 `document.values`；界面所需的轻量列表文档按需生成，不保存第二份实体属性或字段副本。

本地资源包括完整原始文档基线和完整类型、公式。`public/gm` 标记只影响界面字段展示，不过滤同步文档，也不构成联网权限机制。模型凭据、内部运行详情仍不属于文档同步。

| 入口                              | 职责                                                   |
| --------------------------------- | ------------------------------------------------------ |
| `sessions.module.resources`       | 本地冻结模组、完整类型、原始基线、阅读页与玩家流程配置 |
| `tarp://document/…`               | 图片实际加载时在本机解析文档引用                       |
| `game.room.subscribe/acknowledge` | 本局原始覆盖、后续补丁、房间元数据、聊天事件及确认     |
| `game.launch.*` 与 AI 文档命令    | 主机验证并持久化命令                                   |

渲染进程通过本地常驻 Web Worker 使用共享计算器读取计算文档，业务及展示公式由 SES 执行，不向房主服务或桌面 RPC 请求求值；主进程通过同一计算核心进行权威读取和提交验证。创建房间时保留模组完整校验，正常打开房间的冻结资源加载不执行整库公式。

客户端 SES 不授予系统时钟与随机源：`Date.now()`、无参数 `new Date()` 与 `Math.random()` 在 Compartment 内调用失败；显式时间参数的数据处理仍可用。Node 原生校验入口仍可访问这些 API，因此公式应只依赖原始快照，不能利用两端环境差异。游戏随机结果与时间推进由行动写入普通字段，再由公式读取。

## 原始覆盖与版本

例如模组原始值为 `{hp:10, inventory:[...]}`：

| 本局状态            | 累计覆盖                    |
| ------------------- | --------------------------- |
| 没有修改            | 不发送该文档原始字段        |
| HP 变为 7，再变为 3 | 先 `{hp:7}`，再 `{hp:3}`    |
| HP 恢复 10          | 删除 HP 覆盖，回到本地基线  |
| 删除字段            | 显式删除列表，区别于 `null` |
| 新增文档            | 发送新增原始文档            |
| 删除文档            | 文档删除标记                |

累计覆盖的头部保存文档属性差异、属性删除列表、`revision`、可选 `character` 与实体新增/删除标记；`character: null` 表示解除角色归属，省略则沿用基线。普通字段差异与字段删除列表单独保存，`document` 头部不包含 `values`。编码使用 `header` 字符串和逐字段 `fields` Map，客户端合并后只还原一份 `document.values`。文档公式配置 `computed` 独立保存在 `document` 头部，不进入逐字段 `fields` Map；配置变化或删除同样向计算器提交该文档的新输入。

普通字段、对象和数组以字段顶层整体替换；`values` 的字段分别取差异，不因一个 HP 变化发送整份 `values`。名称、正文等文档元数据同样只发送变化。计算结果不进入文档覆盖。

首帧和重连帧是**累计覆盖的完整快照**，不是全部文档的全量传输。后续补丁是累计覆盖自身的变化。角色 ID、控制者和生命周期作为界面索引保留，文档身份由规范相对路径决定。

`documentRevision` 仅在原始文档成功提交后增长。聊天、指标、连接和角色选择不推进它。覆盖索引另有 `overlayRevision`，允许角色绑定更新而不使公式缓存失效。一批完整补丁解码成功后才原子发布版本及文档。

基线版本对冻结模组文件树的路径、内容做 SHA-256，包含类型、配置、阅读页、正文和图片，不依赖计算结果或绝对目录。基线不匹配时明确停止重试；用户恢复本地模组后显式重新读取。

## CPU 工作路径

主机共享按房间缓存的累计覆盖，文档提交只重新读取脏路径、比较这些文档与基线。每个订阅仍有独立 Encoder、序列号和确认窗口。未变的覆盖不重新序列化，只含元数据的事件不遍历覆盖。提交前容量检查按修改文档增量核算。

客户端 Decoder 根据变化引用定位受影响的文档，只解析这些文档的变化字段。未变文档复用对象；只有文档索引发生变化时才复制索引。renderer 适配器在第一次读取时启动 Worker 并同步完整输入，之后合并脏文档与删除路径，在下一次读取前一次同步，不逐版本重建整库输入。UI 保留原始快照副本用于 Worker 重建，引用图、求值及结果缓存只在 Worker 内维护。

共享 `DocumentEvaluator` 索引完整原始输入，但 `readDocument(path)` 计算根目标和它实际读取的多级声明引用。引用属性按需求值，不提前执行目标全部字段；所属文档上下文、类型与布局约束在同一入口内校验。`load()` 返回目标的普通字段，名称和正文使用 `name`、`body` 等属性，不注入另一套特殊别名。每个根入口及其引用链共享字段单元和引用视图；客户端注入 SES 编译器，每个根入口新建 Compartment，同批表达式缓存只在该环境内保留。Node 权威读取与 CLI 默认使用原生编译器，依赖调度和完整 Schema 规则不分叉。

计算字段可以在原始文档中保存同名原值。文档顶层 `computed` 覆盖当前文档的类型公式，原始同步保留该配置，渲染进程与主进程共用有效字段定义；配置不进入计算字段的展示结果。每次求值将业务原值与文档元数据冻结为 `$raw`，公式配置保持独立，`$self`、`$item` 仍是计算视图，结果与输入独立。原始同步、文档覆盖和版本比较只使用原值，不能将展示结果合并回基线。计算字段不能同时标记 `mutable`，运行时变化通过独立普通字段写入。

同一路径复用尚未失效的 Promise，本次求值中的引用视图与字段结果复用；不同入口不共享未完成的字段单元。初次快照扫描全部原始文档，按类型中声明的引用建立直接关系与反向索引，不执行公式。增量输入只更新变更文档的出边，沿变更前后反向引用链清除完整资料及名称缓存；无关文档的计算结果跨版本复用，未读取文档不会计算。草稿不加入真实依赖图，版本更新统一清理草稿缓存。连接与计算器各自最多缓存 128 份草稿输入，连续编辑时淘汰最早条目；淘汰只移除缓存，不取消已有读取者正在等待的计算。主进程的 AI `read` 会核验目标及引用实际原始内容，以保留人工文件修改后的权威读取行为；应用提交由房间锁保护一致性。

角色列表、开局流程读取原始快照；角色和世界卡需要展示计算内容时，按文档路径读取对应投影。没有伙伴时指标查询不读取角色计算视图。多个玩家共用主机的计算任务。

主机在房间目录的单个 `document-references.json` 中保存格式版本、各文档的直接引用、允许的目标类型和业务原值、独立 `computed` 配置及类型定义的 SHA-256 指纹；反向索引由直接关系恢复，不持久化公式结果或进程内版本。创建房间时建立完整索引，运行时同房间连接共享内存索引。文档提交先暂存文档和变化后的索引，再依次原子替换文档与索引；索引暂存失败不发布文档，文档发布失败清理候选索引。索引发布失败时明确报告文档已保存，推进文档版本并丢弃相关内存快照，下次读取按完整原始快照修复索引。

普通属性变化且声明关系不变时只更新内存指纹，不重写整张图；更新后的指纹随下一次关系变化的索引保存合并落盘。重启后首次原始快照核对指纹，复用匹配条目，修复过期条目并移除已不存在文档的出边；索引缺失或 JSON 格式损坏时重新构建；如果目标已是目录、符号链接或特殊文件，则拒绝覆盖。人工修改由权威读取核验，关系变化时同步索引。文档与索引分别原子替换，不保证跨文件崩溃原子性，恢复始终以原始文档为准。

## 渲染端与生命周期

一个房间连接按需创建 `WorkerDocumentEvaluator`，在专属 Web Worker 中持有 `DocumentEvaluator`，业务计算、显示条件、实例态与展示计算都在本地完成。`document-worker.ts` 先加载 SES 并调用 lockdown，再动态导入可信调度代码，UI realm 不冻结。公式仅获得冻结的上下文和计算辅助函数，不能访问 Bun、process、DOM、fetch、Worker、IndexedDB 等宿主能力；`$self` getter 与 `load()` 都在 Worker 内同步运行，不逐字段发消息。

适配器串行调度请求，执行期限从实际发送时开始，不把排队时间计入后续任务。Worker 启动限时 10 秒、快照同步 5 秒、单次文档读取或草稿计算 1 秒。超时或 Worker 错误会终止整个计算环境；本次读取明确失败，后续请求重新创建 Worker、同步最新原始快照，不自动重跑同一条失败公式。关闭房间时立即释放 Worker 并拒绝在途与排队读取。SES 不提供独立堆硬限额，恶意内存分配仍是边界。

生产 CSP 保留 SES 所需的 `unsafe-eval`，通过 `worker-src 'self'` 只允许同源静态 Worker，禁止 blob 和远程 Worker；`connect-src` 仅开放 Electrobun 原生桥使用的本机 WebSocket。Vite 以 ES module 形式构建 Worker 及其动态导入资源。原生导航规则阻止远程页面，UI 不直接访问 Bun 或 Node.js API。

可见文档与角色通过共同读取入口计算。适配器为每次快照变化维护本地代数（即使房间版本相同也区分重置），Worker 返回请求代数，迟到结果被拒绝；房间连接按现有版本规则重新读取。取消某个调用者只结束该调用者等待，不取消其他面板共享的任务。计算缓存每路径只保留一份尚未失效的结果，普通资料在下一版加载期间保留最近成功内容；配置了显示条件的资料，须确认在当前版本可见后才展示，避免撤销揭露后继续呈现旧值。

草稿没有真实实体路径，通过计算器的临时文档入口计算字段、元数据、显示条件和多级引用；临时文档不加入真实索引。草稿身份或房间变化不复用此前的展示结果，实体展示也按房间和查看者隔离。初次加载使用占位内容；计算失败只隐藏对应字段和实际读取它的依赖字段，名称失败使用统一占位，不把原始名称、正文和图片作为计算结果显示。

房间连接的全文与名称读取共用版本检查、过期重读、失败缓存清理和调用者取消逻辑。两种读取仍保留独立的求值与结果投影；全文缓存可以满足名称读取，名称缓存不能替代全文。

引用文字、弹窗标题、表格可见行、背包及装备缩略图均读取本地计算资料，共享同版本路径缓存。引用集合先读取本集合候选条目，再按计算名称搜索；搜索结果与条目使用同一份投影。聊天按 `speakerPath` 读取实际发言 NPC 的公开文档，不通过计算名称或别名猜测身份。名称查询使用惰性字段 getter，只执行访问到的自身字段，并先求值文档显示条件；引用按多级计算规则访问所需字段。实际字段依赖用于单次计算内传播隐藏结果；跨版本失效使用原始文档的声明引用图，不依赖当前公式分支是否访问目标。

房间文档版本变化时触发读取查询刷新，计算器按文档级声明引用保守失效，不提供字段级响应式订阅。未装备等业务状态不会成为平台硬编码的计算规则；声明引用即作为潜在依赖，目标任何字段变化均使引用者失效，即使当前公式分支没有使用它。缺失或类型暂不匹配的目标也保留反向关系，后续新增或替换目标可以清除旧结果；引用环遍历按已访问集合去重，只有实际字段求值循环才是计算错误。

开局展示统一由房间副本和本地计算预览派生，不创建常驻 `game.launch.get` 查询，也不写入第二份开局查询缓存。首次快照尚未到达时显示加载；加载完成且没有开局配置时可以正常进入冒险。共享连接错误和本地预览计算错误均可重试；计算失败时保留最近一次成功预览，显式重试会重建计算器。

选角、确认和建卡返回的命令响应仅更新下一条命令使用的房间与个人进度，分别按 `revision` 接收更新，陈旧渲染不能回退它们。房间切换后重置命令引用，旧房间响应不更新新房间。动作发生冲突时保留错误，按需读取 `game.launch.get` 恢复命令进度，并重新同步显示；不自动重放操作。

每个窗口的面板共享连接和通知流。聊天以事件流标识和游标补发内存通知，窗口过期或房主重开房间时分页刷新已加载范围与离线新增消息，再订阅新流；状态以 streamId/seq/baseSeq 恢复。重复帧忽略，缺帧和解码错误保留最后成功快照并重连。最后离开释放计算器与共享缓存、终止共享任务和订阅；主机通过 `sessions/room-resources.ts` 按数据库连接共同持有房间资源：最后一个连接关闭后释放冻结模组、计算快照、引用索引和投影缓存，短期连接关闭不会使其他活动连接失效。闲置房间只保留最多 32 份轻量文档版本，供连续的短期命令沿用；显式关闭或删除房间时一并清除。通知代数由连接和订阅共同持有，无消费者时删除。

## 容量与存档

磁盘覆盖格式和文件提交边界见[游戏房间存档格式](游戏房间存档格式.md)，传输不另建权威存档。

- 最多 10,000 份文档。
- 单份原始文档最多 1 MiB。
- 累计覆盖最多 8 MiB，包含字段、头部及编码预留开销；在落盘前检查。
- 状态帧最多 10 MiB，额外空间容纳房间元数据和 Schema 编码。
- 每订阅最多 64 条、16 MiB 未确认通知；后者容纳最大状态帧的 base64 封装。确认等待超时为 15 秒。

容量测试验证拒绝后文件与版本不变化，接近覆盖上限的已提交状态仍能重新编码完整快照。

## 性能测量

性能测量原则见[测试维护](测试维护.md#性能测量)。

测量使用 `packages/module/test-fixtures/platform/` 中随 Git 维护的固定功能测试模组，由 `createTestModule()` 复制到独立临时目录，再按场景扩增实体；不读取剧情模组或相邻仓库。对比时使用相同测试数据、运行环境和负载，区分首次初始化与预热后的读取，单独记录是否包含文档提交。报告应注明系统、运行时版本、文档数量、客户端数量和重复次数；本机结果不能作为跨设备延迟承诺。

首次本地读取、内容哈希、声明引用图及快照初始化随模组大小增长，变更时的不可变索引复制与反向引用遍历也有规模成本。
