# 应用管理主持插话队列

主持插话需要逐条撤销、多人权限、关闭开关以及停止和重启后的保留。由应用持久管理未接收队列，在 Pi 的安全接收点批量交接，再把内容投影为玩家聊天消息；Pi 负责已接收上下文和后续模型运行，不作为可撤销队列的权威来源。

Pi 1.1.0 的原生 `steer` 队列只有内存状态与整队列清空能力，消费和落盘之间还存在间隙。直接把所有插话提前装入该队列，或通过清空重建模拟删除，无法可靠区分可撤销内容与已经进入上下文的内容。

这一选择增加 SQLite 与 Pi JSONL 的恢复对账，并要求主持运行与聊天消息分别建模：普通接收继续同一运行，但在插话玩家消息之后新建主持消息。实现采用 Pi 公开 `turn_end` 边界与持久自定义消息，在原生写入成功后提交聊天投影；跨存储失败依据实际分支的批次标记恢复。真实 Pi 集成测试验证整组工具完成后接收、聊天分段、直接打断及重启对账。

完整行为约束、权限、容量与回归范围见[主持插话实现](../游戏聊天与AI实现.md#主持插话)，领域用语见[房间协作术语](../GLOSSARY.md)。
