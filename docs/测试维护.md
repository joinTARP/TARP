# 测试维护

完整平台命令从仓库根目录执行。游戏核心的独立测试在 `packages/core/`，涉及桌面配置、媒体和渲染连接的集成测试保留在 `apps/desktop/`；桌面目录的测试命令只执行桌面范围。

测试统一使用 Bun 内置的 `bun:test`，运行环境与桌面主进程一致。`scripts/test.ts` 负责 workspace 范围和 CLI 预构建，使用 `--isolate` 隔离每个测试文件的模块与全局状态。根级 `bunfig.toml` 加载 `scripts/test-preload.ts`，解析已有 UI 别名并忽略样式导入；TypeScript 与 TSX 由 Bun 原生处理。当前界面测试验证服务端渲染结果，真实界面交互按相关变更手工检查。

数据库直接使用 `bun:sqlite` 与 Kysely，业务查询和事务同步执行，建表在打开连接时完成。开发环境和 CI 使用 Bun 1.4.0 或更新版本。CLI 测试在执行前构建产物，并分别通过 Node.js 和 Bun 验证同一份实际分发入口；这部分测试需要 Node.js 22.12.0 或更新版本，CI 固定最低版本执行。可用 `TARP_CLI_NODE` 指向指定的 Node.js 可执行文件。

测试用于发现独立故障。新增测试应说明具体触发条件、错误结果和用户影响；不按函数数量、文件数量或覆盖率目标补用例。

## 迭代时运行

| 命令                                | 范围与用途                                            |
| ----------------------------------- | ----------------------------------------------------- |
| `bun run test:changed`              | 根据当前 Git 改动及导入关系筛选平台测试，适合日常反馈 |
| `bun run test <文件路径或功能目录>` | 已知修改范围时直接运行相关测试                        |
| `bun run test`                      | 平台完整回归，包含同步、存档、计算核心和界面消费者    |

根目录运行以上命令覆盖整个平台，在应用或包目录执行时只运行对应 workspace。也可以在根目录使用 `bun run test --scope @tarp/core` 指定 workspace。

Git 影响筛选使用 Bun 的导入关系，无法替代运行时协议、磁盘格式和跨进程链路验证，也不会跟踪运行时从磁盘复制的测试模组文件。修改包内固定测试模组时运行 `bun run test`。修改这些边界时运行平台完整回归。改动已提交后，默认影响筛选可能没有结果；此时明确指定文件或用 `bun run test --changed=<提交或分支>` 指定比较基准。性能脚本按相关改动运行，不纳入每次迭代的默认测试。

## 保留与精简

- 驱动替换、重构等开发过程中的临时验证测试，在开发完成后删除，不自动保留为长期回归；长期行为优先由已有功能测试覆盖。
- 简单增删改查优先复用已有业务场景，不为每个接口、字段或透传分支单独补用例；配置合并等改动只增加跨模块覆盖、数据丢失或凭据泄漏等独立风险的验证。
- 仅检查缓存实例身份、内部查询次数或重构接线的测试作为临时验证；长期回归断言业务结果，需要持续跟踪性能时使用独立基准脚本。
- 性能脚本与平台测试使用相同的独立数据原则，不读取相邻仓库、玩家模组或个人存档；测量规模由测试数据扩增，不依赖剧情内容或写死示例模组的文档数量。
- 保留落盘失败不破坏存档、并发写入、版本一致性、同步恢复、计算错误隔离及 Agent 搜索正则限时边界等独立风险。
- 同一消费链路的映射、筛选和最终展示放在已有功能测试中，共用最小数据。不要给每个小辅助函数建立测试文件。
- 字段计算由计算核心验证，界面测试验证计算结果是否被正确消费；不要在每个界面重复公式组合。
- 页面和组件断言围绕可见结果、数据丢失、错误状态及可操作性，不绑定 CSS 类、内部节点数量或无关文案。
- 相同输入和相同代码路径的重复检查删除；真实不同的边界保留清楚的场景，不能仅为降低数量合并成难排查的大测试。
- 重试、取消等时间行为使用 `@tarp/module/testing/async` 的 `useFakeTimers` 模拟时间；同步计时器用 `advanceTimersByTime` 推进，涉及 Promise、文件或网络操作时用 `await advanceTimersByTimeAsync`。`useFakeTimers` 已注册测试结束时的自动恢复；需要在测试中途恢复真实时钟时调用 `useRealTimers`。文件或消息操作使用独立临时数据并清理；单个测试的清理使用 `bun:test` 的 `onTestFinished`。
- 剧情模组的规则数值、剧情路线与素材完整性由各模组仓库自行验收，具体入口见对应仓库的 README。平台共用测试模组维护在 `packages/module/test-fixtures/platform/`，随 Git 提交，只覆盖平台功能，不包含剧情逻辑。`createTestModule()` 将固定模组复制到独立临时目录，测试只修改副本并在结束后清理；特殊错误与边界数据由对应测试在副本中构造。

## 性能测量

按实际性能问题临时构造独立测试数据，测量前明确输入规模、客户端数量、是否包含磁盘读写、初始化或预热，以及耗时、CPU、内存和传输量的统计边界。完成验证后清理临时驱动，不将实验脚本自动保留为长期维护入口。

房间同步的测量边界和规模成本见[房间增量同步实现](房间增量同步实现.md#性能测量)。
