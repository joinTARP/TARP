# 游戏状态实现

状态建模和展示配置维护在官网的状态与布局文档。本文说明状态的权威来源、通用提交与展示、主持上下文，以及房间生命周期的约束。

## 模组状态与平台职责

游戏事实来自房间 `module/` 与 `game/` 的合并视图。`module/` 是基础模组，`game/` 保存本局字段差异；聊天记录和开局背景不能替代当前文档值。

位置、场景、参与者、时间、回合、行动顺序、效果与胜负条件均由模组通过普通字段和规则定义。平台不按字段名识别玩法，不建立场景归属或入场状态，不自动安排同行、推进回合、解除效果或因文档值变化结束冒险。模组可以使用自己的标识、引用、列表、对象或计算字段建模。

字段类型、枚举、可修改性、引用目标、计算结果和存储容量仍由通用文档契约检查；玩家与 AI 队友对角色的控制权归平台协作协议管理。配置了开局流程时，行动要求角色已确认且开场流程完成；未配置开局流程时不执行这一检查，也不额外要求场景入场。纯预写开场不自动改写模组状态；需要一次性初始化时，由模组开局指令明确要求主持保存。开局背景来自方案简介与叙述；初始位置等玩法事实保存在模组自定义文档中，不由平台开局字段指定。

## 状态读取与展示

主持每轮通过 `sessions/game-context.ts` 获得世界文档和已控制角色的资料入口。索引不注入状态值，也不包含玩法字段映射；裁定使用本轮订阅或按需读取的最新字段。队友获得身份、公开参与者和近期公开交流，位置与已知信息按模组及主持裁定解释，不注入平台推断的场景或发言场景标记。

世界卡按 `designation: "world_state"` 定位，支持同类型或不同类型的多份状态文档。配置 `layout.sheet` 的文档按房间资料索引顺序逐张显示于左侧小队下方，以公开计算后的文档名称为标题，分别折叠并与小队共用滚动区；角色卡位于右侧面板。每张卡独立读取和订阅当前公开投影，隐藏或读取失败不影响其他卡片。初始校验与运行时写入不限制世界文档数量。世界卡与角色卡共用完整 `DocumentSheet`，通过统一 Web Component 宿主展示作者的 HBS 模板、条件和引用、物品格等宿主交互组件。展示不要求状态绑定。

纯引用列表使用通用引用集合的 `display: "sheets"` 嵌入目标文档自己的布局；目标未配置 `sheet` 时按详情字段生成布局。它可以展示怪物、任务或其他资料，名单及出现条件均由作者定义。实际状态保存在目标文档，名单仅维护引用。条目实例状态使用实例展示，不与独立文档卡片混用。

嵌入卡片复用房间文档公开计算投影、查询缓存和详情入口。隐藏资料撤下，读取失败可重试；循环引用及超过四层的嵌入收起为详情入口。平台不从聊天、类型名或图片推断状态。

房间同步只传递通用文档、角色控制和开局、运行等平台区段，不附加固定玩法状态快照。版本推进后按当前文档重新计算，迟到结果不得补回旧值，详见[房间增量同步](房间增量同步实现.md)。

角色卡侧栏的宽度、窄窗口抽屉和焦点恢复见[界面设计](界面设计.md#文档容器与侧栏)。

## 明确结束冒险

`sessions/adventure-status.ts` 维护游戏文档可写性和明确结束操作。主持按模组规则判断整段冒险何时结束，先保存必要结算，再调用 `end_adventure`。工具与文档提交共用房间状态锁，重复调用幂等，不重复改变结束时间；不读取特定结局字段或枚举值。

结束后的房间拒绝资料创建、修改、掷骰和新行动，当前主持可以完成公开尾声。结束和重新开启仍通过现有房间管理操作完成，不由模组某个字段值隐式决定，也没有专用的不可重开玩法状态。

跨文档发布仍可能部分成功；失败后应读取已提交事实继续，不能重复扣除资源。结束操作不代替结算、不回滚已写入数据，取消生成也不撤销状态。

## 验证

回归覆盖多份状态文档的校验、创建、独立更新、恢复和展示，模组自定状态结构、通用引用和写入约束、角色占用、公开投影、嵌入布局、循环引用、同步恢复，以及明确结束后的持久化、尾声和操作拒绝。测试使用独立模组副本，规则见[测试维护](测试维护.md)。
